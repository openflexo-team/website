# Get involved

Openflexo is built by a small team, and grows through outside contributions in several forms, not
only code:

* **Code** — the infrastructure spans about fifty repositories, from the expression language
  (`connie`) up through the modeling framework, the GUI layers, `openflexo-core`, the technology
  adapters and the applications built on top of them. See [Develop](/docs/develop/setup) to set up a
  workspace, and [Write a technology adapter](/docs/develop/guides/write-a-technology-adapter) if
  you want to connect a new kind of resource — federating a new file format, protocol or external
  tool is one of the highest-leverage contributions.
* **Content built with Openflexo** — any graphical domain-specific language (a UML-like notation,
  a process editor, a domain-specific diagram editor…) can be designed with Openflexo itself,
  without writing code. Sharing one you built for your own use case benefits the whole community.
* **Documentation** — this site and the per-component reference material are actively being
  rebuilt; a practitioner's account of using Openflexo for a real case is exactly what is missing
  today.
* **Testing and bug reports** — trying a current build (see [Downloads](/downloads)) and reporting
  what breaks is useful on its own.

To report an issue or start a conversation, use GitHub — either the
[website repository](https://github.com/openflexo-team/website/issues) for anything about this
site, or the relevant component repository under the
[openflexo-team organisation](https://github.com/openflexo-team) for anything about the software
itself. For anything else, [contact us](mailto:contact@openflexo.org).
